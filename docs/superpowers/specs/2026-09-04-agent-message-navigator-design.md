# Agent 历史消息导航轨道设计规格

## 目标

在 Agent 会话消息区域左侧增加类似 Codex 的历史消息导航轨道。轨道只标记用户发送的消息，支持悬停预览和点击跳转，让用户可以在长会话中快速回到之前的请求。

## 非目标

- 不修改章节编辑器或笔记编辑器的行号功能。
- 不为 Agent 回复、思考过程、工具调用、状态消息或子 Agent 节点建立导航点。
- 不新增后端接口、数据库字段或持久化设置。
- 不替代会话内搜索，也不增加消息全文搜索。
- 不在窄屏或移动端显示导航轨道。

## 方案选择

采用 `react-virtuoso` 的索引跳转能力，而不是查找 DOM 节点或根据滚动百分比估算位置。

当前 Agent 消息列表经过分块、折叠和虚拟化，屏幕外的消息可能没有对应 DOM 元素。使用 `VirtuosoHandle.scrollToIndex()` 可以直接定位尚未挂载的消息，并与现有虚拟列表高度测量机制配合。百分比估算会因为用户消息、Agent 回复和工具卡片高度差异而产生明显偏差。

## 用户体验

### 显示条件与位置

- 导航轨道位于 Agent 消息视口的左侧内边缘，不改变右侧输入区和会话头部布局。
- 当前会话至少有两条可见用户消息时显示；只有一条或没有用户消息时隐藏。
- 窄屏和移动布局隐藏轨道，避免压缩消息正文。
- 轨道固定在消息视口中，不随消息正文滚出屏幕，也不产生独立滚动条。

### 导航点

- 每条可见用户消息对应一条短横线。
- 导航点从上到下按用户消息的会话顺序均匀排列，不尝试按正文实际像素位置缩放。
- 当前所在轮次的导航点更长、更亮；其他导航点保持低对比度。
- 消息数量较多时压缩点间距，使全部导航点仍容纳在当前轨道高度内。
- 回滚、分支、重新载入或折叠状态改变后，导航点从当前 `visibleMessageBlocks` 重新计算，不保留已消失消息的陈旧索引。

### 悬停预览

- 鼠标悬停导航点时，在轨道右侧显示浮层。
- 浮层显示消息发送时间和正文摘要。
- 摘要移除 Markdown 标记、mention 展示语法和多余空白，最多保留约 100 个字符，超出显示省略号。
- 图片或附件消息没有可用文本时显示本地化的“用户消息”。
- 浮层不得遮挡导航点本身，离开导航点或浮层后关闭。

### 点击跳转

- 点击导航点调用虚拟列表的 `scrollToIndex({ index, align: "start" })`，把对应用户消息定位到视口顶部附近。
- 采用平滑滚动；用户启用系统“减少动态效果”时改为即时跳转。
- 点击当前导航点也允许重新对齐到该消息，不视为无效操作。
- Agent 正在输出时点击历史点，会关闭当前的自动跟随底部状态，避免流式内容下一帧立即把视口拉回底部。
- 用户之后主动滚动回底部时，沿用现有逻辑恢复自动跟随。

## 当前轮次判定

`Virtuoso` 会预渲染视口上下方的缓冲内容，因此渲染范围起始索引不等于用户真正看到的起始位置。当前项根据已挂载消息块相对滚动视口顶部的实际位置判定，同时仍使用 `Virtuoso` 的索引 API 完成跳转。当前导航点规则为：

1. 找出可见范围起始索引之前或等于该索引的最后一个用户消息块。
2. 若可见范围从首个用户消息之前开始，则激活第一个用户消息。
3. 若列表位于底部状态区或最后一轮 Agent 输出中，保持最后一个用户消息为当前项。

这种判定把一次用户请求及其后续 Agent 输出视为同一轮次，符合“回到之前发送的内容”的导航语义。

## 组件与数据流

新增两个职责明确的单元：

- `agent-message-navigator.tsx`：只负责轨道、导航点、悬停浮层和点击事件。
- `agent-message-navigation.ts`：提供用户导航项提取、摘要生成和当前项计算的纯函数。

`agent-messages.tsx` 保持消息分块和虚拟列表的所有权，并完成以下连接：

```text
messages
  -> normalizeDisplayMessages
  -> buildAgentMessageBlocks
  -> getVisibleAgentMessageBlocks
  -> 提取用户导航项及其 visibleMessageBlocks 索引
  -> AgentMessageNavigator

滚动视口 + 已挂载消息块位置
  -> 当前真实可见起始索引
  -> 计算当前用户导航项
  -> 高亮对应导航点

点击导航点
  -> 关闭自动跟随底部
  -> VirtuosoHandle.scrollToIndex(targetIndex)
```

导航组件接收已经计算好的数据，不读取会话 store，也不理解 Agent 消息分块内部结构。这样消息归一化或分块规则变化时，只需要调整纯数据适配层。

## 数据结构

前端内部导航项使用以下形状，不进入 API 类型：

```typescript
interface AgentMessageNavigationItem {
  id: string;
  blockIndex: number;
  preview: string;
  timestamp?: number;
}
```

`id` 来自用户消息块的稳定 ID；`blockIndex` 必须是当前 `visibleMessageBlocks` 中的索引，不能使用原始消息数组索引，否则折叠或过滤后会跳转到错误位置。

## 布局与可访问性

- `agent-messages-root` 作为轨道的定位容器，使用窄网格列为正文保留少量左侧安全空间。
- 轨道在该窄列中使用粘性定位，不随正文滚出视口。
- 每个导航点使用真实 `button`，提供包含序号和摘要的本地化 `aria-label`。
- 键盘聚焦时显示清晰轮廓；Enter 和 Space 触发与点击相同的跳转。
- 颜色使用现有 Radix 灰阶和 accent token，兼容明暗主题。
- 在项目现有移动端断点下隐藏轨道，并取消正文额外左间距。

## 错误与边界处理

- 目标项在点击前因回滚或消息刷新消失：重新按 ID 查找当前索引；找不到则忽略点击。
- `Virtuoso` 尚未挂载：导航点可渲染但点击不执行，不显示错误提示。
- 消息正文为空或只包含附件：使用本地化兜底摘要。
- 极长正文：在生成摘要前规范化空白，只保留约 100 个字符，不在 tooltip 中渲染 Markdown。
- 大量用户消息：通过计算间距压缩轨道，不截断导航项，也不增加第二个滚动条。
- 流式输出更新高度：依赖 Virtuoso 的测量与索引定位，不缓存目标像素位置。
- 会话切换：导航数据、可见范围和当前项随新 `visibleMessageBlocks` 一起重置。

- 修改 `frontend/src/features/assistant/components/agent/agent-message-blocks.css`，增加轨道、导航点、浮层和响应式样式。

不修改 Assistant 后端、会话传输、消息持久化、编辑器或设置页面。

## 最小验证范围

遵循项目当前的精简测试要求，本功能不新增单元测试或 E2E。

- 运行前端 TypeScript 类型检查。
- 运行前端 lint 和 production build。
- 人工打开一个包含多轮消息的会话，一次性验证导航点数量、悬停摘要、点击历史点、当前点高亮、流式输出时停止跟随以及窄屏隐藏。

## 验收标准

- 至少两条用户消息的桌面 Agent 会话显示左侧导航轨道。
- 每个导航点只对应一条用户消息，顺序和数量正确。
- 悬停能看到该消息的时间及简短纯文本摘要。
- 点击能定位到对应用户消息，即使它此前不在虚拟列表 DOM 中。
- 当前导航点随滚动切换，并在 Agent 回复区域保持对应用户轮次高亮。
- Agent 输出期间点击历史消息不会被立即拉回底部。
- 回滚、分支、会话切换和折叠后不会跳转到错误消息。
- 窄屏和移动端不显示轨道。
- 不影响现有消息虚拟化、滚动到底部、回滚、分支和工具消息展示。
