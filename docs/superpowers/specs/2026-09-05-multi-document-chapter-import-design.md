# 多文档章节导入设计规格

## 目标

扩展现有项目导入能力，使用户在新建项目和已有项目中都能一次选择多个 TXT 或 Markdown 文档、调整文件顺序、预览解析结果并原子导入。已有项目中的导入结果始终创建新卷，可追加到项目末尾或插入当前卷之后；多个文件还可以合并成一个新卷，并按用户选择保留标题或统一增加连续章节编号。

## 非目标

- 多文件模式不接受 ZIP；现有单文件 ZIP 项目导入保持兼容。
- 不导入 DOCX、PDF、EPUB 等富文档格式。
- 不把章节追加到已有卷内部，也不覆盖已有章节。
- 不在导入后保留文件之间的同步关系。
- 不新增全量前端 E2E，仅保护事务和排序等高风险行为。

## 方案选择

采用“前端维护有序文件列表，后端一次接收并事务写入”的方案。前端逐文件调用旧接口会产生部分成功状态，也难以保证插入卷时的连续位置；在浏览器中先拼接文本则会丢失文件名、编码和文件边界。新接口复用现有 `parse_project_import` 解析规则，但把多文件编排和目标项目写入放在独立服务中。

## 用户流程

### 文件选择与排序

新建项目导入和项目内导入共用多文件选择体验：

1. 选择一个或多个 `.txt`、`.md` 文件，也可继续追加文件。
2. 文件列表显示名称和大小，支持拖拽调整顺序及单项移除。
3. 选择自动识别章节或按固定字数分割；该设置应用于本次导入的全部文件。
4. 选择“分别生成卷”或“合并到一卷”。
5. 查看按最终顺序生成的卷、章节、字数和内容摘要，再确认导入。

文件顺序是稳定输入：预览、确认请求和最终卷/章节顺序必须一致。预览完成后若文件顺序或分割设置改变，旧预览立即失效，必须重新预览。

### 分别生成卷

- 每个文件单独解析。
- 文件内识别到明确卷标题时保留这些卷及其章节顺序。
- 文件内没有卷标题时，生成一个以去除扩展名后的文件名命名的新卷。
- 多个文件生成的卷按文件列表顺序依次展开；同一文件内的卷保持解析顺序。

### 合并到一卷

- 用户填写一个新卷名称，默认取第一个文件去除扩展名后的名称，允许修改。
- 所有文件解析出的章节按文件顺序及文件内顺序合并到这个新卷，解析出的卷层级不再保留。
- “保留原章节标题”保持解析结果中的章节标题不变。
- “统一连续编号”把非空原标题变为 `第 N 章 原标题`，空标题变为 `第 N 章`；`N` 从 1 开始跨所有文件连续递增。
- 如果原标题已经以可识别的“第…章”前缀开头，先移除该前缀再加新编号，避免产生 `第 1 章 第十章`。

### 已有项目中的位置

项目内导入入口位于章节侧栏的导入操作中。导入生成的新卷可选择：

- “追加到项目末尾”：第一个新卷位于当前最后一卷之后。
- “插入当前卷之后”：第一个新卷位于用户发起导入时的当前卷之后，其余新卷按预览顺序紧随其后；原本位于后面的卷整体顺延。

没有当前卷时只允许追加到项目末尾。导入期间切换编辑标签不改变已捕获的目标卷；若目标卷在确认前已被删除，后端拒绝请求并要求重新选择位置。

### 新建项目

现有项目导入弹窗从单文件扩展为有序多文件。书名、简介和封面流程保持不变。导入产生的卷从顺序 1 开始写入；单文件 TXT、Markdown 和 ZIP 的现有行为保持可用，ZIP 不能与其他文件组成多文件请求。

## API 与数据流

预览接口接受 multipart 中按顺序重复出现的 `files` 字段，以及：

- `split_mode`: `auto` 或 `manual`
- `chunk_size`: 手动分割字数
- `structure_mode`: `separate_volumes` 或 `merge_volume`
- `merged_volume_title`: 合并模式的新卷名称
- `chapter_title_mode`: `preserve` 或 `continuous_numbering`

项目内执行接口另外接受：

- 路径中的 `project_id`
- `placement`: `append` 或 `after_volume`
- `after_volume_id`: 插入当前卷之后时必填

新建项目执行接口继续接受书名、简介和封面。为兼容旧客户端，原 `file` 单文件字段和原接口继续保留；多文件使用新的 `files` 契约。预览结果不作为可信写入载荷，执行接口重新读取、校验并解析全部文件，防止客户端篡改章节内容或使用过期预览。

数据流：

```text
按 multipart 顺序读取文件
  -> 校验扩展名、单文件和总大小
  -> 逐文件复用现有解析器
  -> 按结构模式规范化卷与章节
  -> 校验章节内容上限
  -> 返回预览或进入数据库事务
  -> 计算目标卷起始顺序并整体腾位
  -> 批量创建卷、章节和写作活动记录
  -> 更新项目统计并提交
```

## 后端职责

- 新增聚焦的多文件编排模块，负责有序文件解析、卷结构展开、合并卷和连续编号；它不访问数据库。
- `import_service` 继续负责新建项目导入，并复用规范化后的卷列表。
- 新增项目内章节导入服务，负责项目/目标卷校验、卷顺序腾位、批量创建章节、活动记录和项目统计。
- 路由只负责 multipart 参数、鉴权、文件读取和业务错误转换。
- 现有卷和章节服务保持原有单项编辑职责，不把批量导入逻辑塞入前端循环。

整个项目内写入使用一个数据库事务。任一文件解析失败、章节超限、项目不存在或目标卷失效时，不创建任何卷或章节，也不修改项目统计。

## 校验与错误处理

- 多文件模式至少包含一个文件，且只允许 TXT、Markdown。
- 文件数量上限为 100；单文件上限沿用现有 50 MB，总上传上限为 100 MB。
- ZIP 仅允许走兼容的单文件项目导入入口。
- 合并模式要求去除首尾空白后的新卷名称非空，最长 200 字符。
- 插入模式要求 `after_volume_id` 属于目标项目。
- 每章正文沿用编辑器内容上限校验；所有文件校验完毕后才写数据库。
- 文件顺序变化或重新选择后，前端用请求序号丢弃迟到的旧预览。
- 服务端错误时保留文件顺序和用户选项，允许修改后重试。

## 前端结构

- 抽取可复用的有序文件列表组件，负责添加、移除和 `dnd-kit` 拖拽，不负责调用 API。
- 抽取多文件导入选项和预览模型，供新建项目弹窗与章节侧栏弹窗共用。
- 新建项目继续使用现有 `ImportDialog` 外壳，替换其单文件状态和预览请求。
- 项目内新增轻量导入弹窗，从写作页接收 `projectId` 和当前 `volumeId`，成功后失效卷树查询并选中第一个新建章节。
- 中英文文案覆盖文件排序、结构模式、标题模式、插入位置、校验和结果统计。

若现有 `ImportDialog` 因共用逻辑继续增长，只抽取文件列表、选项和预览三个职责明确的子组件，不重构无关的封面或完成页。

## 预计修改范围

### 后端

- `backend/app/core/project_import.py` 或同目录新模块：多文件规范化和标题编号。
- `backend/app/api/schemas/import_schema.py`：多文件预览与项目内导入响应。
- `backend/app/api/routers/import_router.py`：新建项目多文件预览/确认兼容入口。
- 新增项目内章节导入路由或在章节路由中增加聚焦端点。
- `backend/app/storage/services/import_service.py`：复用规范化卷列表。
- 新增项目内导入服务：事务写入、卷腾位、统计和活动记录。
- `backend/tests/api/test_import.py`：少量关键接口测试。

### 前端

- `frontend/src/features/projects/lib/import-api.ts`：多文件请求类型与 multipart 构造。
- `frontend/src/features/projects/components/import-dialog.tsx`：新建项目多文件流程。
- 新增有序文件列表和共用导入选项组件。
- `frontend/src/features/writing/components/chapter-sidebar.tsx`：项目内导入入口。
- 新增项目内章节导入弹窗。
- `frontend/src/i18n/locales/en.json`、`zh-CN.json`：相关文案。

## 最小测试与验收

按用户要求控制测试数量。后端新增四个聚焦用例：

1. 多文件顺序决定新建项目的卷顺序。
2. 项目内导入的新卷可插入指定当前卷之后，原卷顺序连续顺延。
3. 合并模式跨文件连续编号为 `第 N 章 原标题`，且不会保留旧章节号前缀。
4. 后一个文件校验失败时，项目内不产生任何部分数据，统计和卷顺序不变。

前端只运行类型检查、Lint 和生产构建，并人工检查一次：选择多个文件、拖拽换序、分别生成卷、合并连续编号、项目末尾追加和当前卷后插入。旧的单文件 ZIP 新建项目导入也走查一次。

验收完成时：

- 新建项目和已有项目均可选择、追加、移除及排序多个 TXT/Markdown 文件。
- 预览与最终结果严格遵循文件顺序。
- 分别生成卷时保留文件内识别出的卷结构；合并时只生成一个可命名的新卷。
- 连续编号保留原标题但替换原章节号前缀。
- 项目内导入只创建新卷，可追加末尾或插入发起操作时的当前卷之后。
- 任一失败不会留下部分卷、章节、活动记录或错误统计。
- 原有单文件 TXT、Markdown、ZIP 新建项目导入不回归。
