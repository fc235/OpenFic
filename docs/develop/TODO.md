### T01 自动保存必须区分成功、失败和跳过

- [x] 修正保存结果契约，并让界面明确区分本地草稿与服务端已保存。
- **完成记录（2026-09-05）**：自动保存回调现在返回 `saved / skipped / failed`，只有服务端确认成功才推进保存时间；章节和笔记失败后保持未保存状态与本地 working copy。
- **证据**：`frontend/src/features/writing/hooks/use-auto-save.ts` 的 `save()` 在 `await onSave()` 后直接写入 `lastSaveTime`；`chapter-editor.tsx` 的 `handleSave` 捕获异常后只同步脏状态，`note-editor.tsx` 捕获后只保留未保存状态，没有向 Hook 返回失败。锁定、内容超限等分支也可能正常返回。
- **影响**：Hook 可能把失败或跳过的保存记录为成功时间。是否已被所有页面展示，需要检查调用方；不能据此断言正文已丢失，现有 working copy 已提供本地草稿保护。
- **建议**：保存回调返回明确结果，例如 `saved / skipped / failed`；仅在服务端成功确认后更新时间。失败保留草稿和重试入口。后续把章节、笔记重复的保存收尾逻辑收敛为小型公共 Hook。
- **定位**：上述三个文件；`frontend/src/features/writing/hooks/use-writing-working-copy.ts`。
- **最小验收**：一次正常保存、一次断网失败、一次锁定跳过；失败后时间不推进，草稿仍在，重试可成功。适合一条聚焦保存结果的测试，不扩展全套编辑器 E2E。
- **工作量**：中；涉及保存语义，先修结果契约，再考虑抽取公共逻辑。

### T02 修正 PWA 缓存版本和资源范围

- [x] 为每次构建生成缓存版本，限定静态资源缓存范围，并清理旧版本。

- **最小验收**：连续两个构建升级、打开旧标签页、离线重载各检查一次；确认新版本可用、旧缓存可回收、资产不会被误当作固定应用文件。
