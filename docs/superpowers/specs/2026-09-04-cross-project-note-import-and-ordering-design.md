# 跨项目笔记导入与树形排序设计规格

## 目标

扩展现有笔记导入功能，使用户可以从另一个项目选择部分分类或笔记并导入当前项目。同时为笔记树增加持久化拖拽排序，让同一层级中的分类和笔记可以按用户指定的混合顺序排列。

## 非目标

- 不删除或移动来源项目中的任何内容。
- 不支持在一次操作中从多个来源项目导入。
- 不改变现有 Markdown、ZIP 文件导入和笔记导出流程。
- 不引入跨项目实时同步；导入得到的是一次性副本。
- 不复制来源笔记的锁定或 Agent 隐藏状态。
- 不增加单独的“排序模式”或手动保存按钮。
- 不扩展现有分类最大层级。

## 现状与方案选择

现有笔记导入只接受 Markdown 或 ZIP 文件。笔记树已经使用 `dnd-kit` 支持把笔记或分类移动到其他分类，但 `Note`、`NoteCategory` 没有排序字段，因此同一分类内的手动顺序无法保存。

项目中的章节目录和世界观条目已有拖拽排序及持久化能力；编辑器标签页也支持拖拽。因此，笔记采用相同的即时保存交互，与其他主要目录功能保持一致。

跨项目导入采用后端原生复制方案，而不在前端模拟逐条创建，也不先生成内部 ZIP：

- 后端可以统一校验项目归属、分类层级、冲突策略和事务完整性。
- 预览与执行可以共享同一套选择和冲突计算逻辑，避免界面展示与实际结果不一致。
- 导入过程可在单个事务中完成，任何失败都不会留下半成品。

## 用户体验

### 导入入口

保留现有“导入笔记”入口，并把对话框分成两个来源：

- 从文件导入：保持当前 Markdown、ZIP 流程。
- 从其他项目导入：使用本设计的新流程。

选择“从其他项目导入”后：

1. 选择一个来源项目；列表不显示当前项目。
2. 在可展开的笔记树中勾选分类和笔记。
3. 预览将创建或合并的结构以及同名冲突。
4. 选择本次导入的默认笔记冲突策略，并可逐项覆盖。
5. 确认后执行导入，完成时刷新当前项目笔记树并展示结果统计。

### 选择规则

- 勾选分类时，默认勾选它当前包含的全部子分类和笔记。
- 用户仍可展开该分类，取消勾选任意后代条目。
- 取消勾选分类会取消其全部后代；重新勾选会重新选择其全部后代。
- 分类被部分选择时显示半选状态。
- 单独选择一条深层笔记时，系统隐式包含重建其路径所需的祖先分类，但不会因此导入未选择的同级内容。
- 没有选择任何笔记或分类时，确认按钮禁用。

### 冲突处理

冲突以“目标父分类下名称相同”为判断范围，不跨层级比较。

- 同名分类总是合并，并在合并后的分类中继续递归处理选择项。
- 同名笔记支持“自动重命名”“覆盖”“跳过”三种策略。
- 用户先选择一个适用于本次导入的默认策略，再对预览中任意一条冲突设置单独策略。
- 自动重命名使用稳定的递增后缀，例如 `人物设定 (2)`、`人物设定 (3)`，选择第一个未占用名称。
- 覆盖只更新目标笔记的标题和正文内容，保留目标笔记原有位置、锁定状态和 Agent 隐藏状态。
- 跳过不会修改目标笔记，也不会创建副本。

新创建的笔记一律使用目标项目新建笔记的默认状态：不锁定、Agent 可见。界面不提供“保留或重置状态”的额外选项。

### 完成反馈

导入成功后显示创建、覆盖、跳过数量。新建分类和笔记追加到对应目标层级的末尾，并保持来源项目中的相对顺序；合并的已有分类和被覆盖的已有笔记保持目标项目中的原位置。

## 数据模型与排序语义

为 `Note` 和 `NoteCategory` 分别增加非空整数 `order_index`，默认值为 `0`。两种实体在同一个父分类下共享一条混合顺序：分类使用 `parent_id` 表示父级，笔记使用 `category_id` 表示父级，根层级均以 `null` 表示。

迁移现有数据时，以当前 API 返回的稳定显示顺序为基准，为每个父层级中的分类和笔记写入连续序号，避免升级后界面顺序发生无意义跳变。以后读取时先按 `order_index` 排序，并使用实体类型和 ID 作为确定性兜底顺序。

每次写入排序后，后端把受影响父层级的序号压缩为从 `0` 开始的连续整数，避免长期拖拽产生空洞或重复值。

## 拖拽交互

笔记树沿用现有拖拽手势，并区分两个落点：

- 落在分类主体上：把条目移动到该分类内部，并放在末尾。
- 落在条目上方或下方：把条目放到同一父层级的指定位置。

分类与笔记可以在同一父层级中任意交错。拖拽松开后前端立即乐观更新树并提交，不增加保存按钮。请求失败时恢复拖拽前顺序并显示错误提示。

移动和排序由一个原子后端操作完成。请求包含被移动条目的类型与 ID、目标父分类 ID，以及移动后目标父层级的完整混合条目序列。后端在事务中：

1. 校验条目和目标父分类都属于当前项目。
2. 校验分类不会移动到自身或后代中，且结果不超过现有层级限制。
3. 校验目标序列没有重复、遗漏或额外条目。
4. 更新条目的父级，并重新编号来源和目标父层级。

同一父层级内的纯排序走相同接口。这样可以避免“先移动、再排序”两次请求之间出现短暂不一致。

## 跨项目导入接口与数据流

新增独立的跨项目预览和执行接口，避免改变现有 multipart 文件导入契约。建议路由为：

```text
POST /projects/{target_project_id}/notes/import/project/preview
POST /projects/{target_project_id}/notes/import/project
```

两个请求共享以下核心输入：

- `source_project_id`
- 明确选中的分类 ID 和笔记 ID
- 默认笔记冲突策略
- 以来源笔记 ID 为键的逐项冲突策略覆盖

预览接口只读数据库，返回规范化后的选中树、隐式包含的祖先分类、每项预计动作以及汇总数量。执行接口重新进行全部校验和冲突计算，不能信任客户端提交的预览结果。

执行顺序：

```text
验证来源/目标项目及选择归属
  -> 规范化选择并补齐必要祖先
  -> 按来源混合顺序遍历
  -> 创建或合并分类，建立来源到目标分类映射
  -> 按默认策略及逐项覆盖处理笔记
  -> 为新条目分配目标层级末尾的连续 order_index
  -> 提交事务
  -> 返回统计并由前端刷新笔记树
```

来源项目始终只读。若任何一步失败，整个事务回滚。

## 后端职责边界

- `note_transfer_service` 扩展为跨项目导入的编排层，负责选择规范化、预览、分类映射、冲突决策和复制。
- `note_service` 负责统一树顺序、移动与重新编号，不把排序算法放进 API 路由。
- API schema 明确定义混合条目标识（`category` 或 `note`）、冲突策略、预览动作和导入统计。
- 路由只负责鉴权、解析请求、调用服务并转换已知业务错误。

预览与执行必须调用同一套纯计算辅助逻辑。执行阶段在锁定的数据库状态上重新计算，保证预览后目标项目发生变化时仍按最新数据安全处理。

## 校验与错误处理

后端拒绝以下请求，并返回可展示的 4xx 错误：

- 来源项目与目标项目相同。
- 来源或目标项目不存在，或当前用户无权访问。
- 选择 ID 不属于指定来源项目，或类型与 ID 不匹配。
- 冲突覆盖引用未选中的笔记。
- 导入结果会超过现有分类层级限制。
- 拖拽目标不属于当前项目、形成分类循环，或提交的完整同级序列不合法。

预览后若目标项目内容发生变化，执行结果可能与旧预览不同；执行接口以当前数据库状态重新计算并返回最终统计。对于服务端错误，前端保留用户当前选择和冲突设置，方便重试。

## 前端组件调整

- `note-import-dialog.tsx` 增加来源切换、项目选择、可勾选树、预览和冲突策略区域；文件导入状态与跨项目导入状态相互隔离。
- 新增小型跨项目导入 API 类型与请求函数，避免把复杂数据拼装散落在组件中。
- `note-tree.tsx` 和 `note-tree-item.tsx` 扩展落点计算及乐观排序；现有移动行为合并到新的原子排序请求。
- 笔记树的客户端模型保留后端提供的 `order_index`，渲染前将分类和笔记合并排序。
- 导入完成只失效当前目标项目的笔记查询，不修改来源项目缓存。

若导入对话框因新增流程明显过大，应把“来源项目选择树”和“冲突列表”拆成职责单一的子组件，不进行与本功能无关的笔记侧栏重构。

- `frontend/src/lib/note.types.ts`：增加顺序与跨项目导入类型。

## 最小验证范围

按用户要求避免为实现细节堆叠测试，只覆盖容易造成数据损坏或核心流程失效的边界。

### 后端测试

- 选择分类后取消部分后代，执行结果与预览一致，并自动补齐必要祖先。
- 同名分类合并；同名笔记的重命名、覆盖、跳过及逐项覆盖得到正确结果。
- 新笔记不复制锁定/隐藏状态，覆盖笔记保留目标状态和位置。
- 非法跨项目 ID 或任一步骤失败时不产生部分导入。
- 分类与笔记的同层混合排序可持久化；非法循环、超层级和不完整序列被拒绝。

### 前端验证

- TypeScript 类型检查和 lint 通过。
- 一条聚焦 E2E 覆盖：选择来源项目、部分选择、处理一次冲突、完成导入，并拖拽一个条目后刷新确认顺序保留。

不为每个按钮文案、展开状态或所有策略组合分别编写重复 E2E。

## 验收标准

- 用户可以从任意其他可访问项目中选择部分分类或笔记导入当前项目。
- 选择分类默认包含后代，同时允许取消任意单项。
- 来源分类层级和所选条目的相对顺序得到保留。
- 同名分类自动合并；同名笔记支持全局策略和逐项覆盖。
- 导入操作是事务性的，来源项目不被修改。
- 新导入笔记默认不锁定且对 Agent 可见，不显示额外状态选择。
- 分类和笔记在同一父层级共享顺序，可通过拖拽移动或重排，并在松开后立即持久化。
- 章节目录和世界观条目已有排序能力保持不变，不做无关修改。
- 原有 Markdown、ZIP 导入与导出行为不回归。
